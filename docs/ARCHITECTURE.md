# 实现与协议

## 应用边界

前端为 Svelte 5 单页应用，使用 Vite 8（Rolldown）构建与 Tailwind CSS 4。Bun 提供 HTTP、WebSocket 和构建后的静态资源；`bun:sqlite` 存储场次、凭证摘要和命令去重记录。具体锁定版本、Bun 运行时与类型包的区别，以及 Svelte 插件对 Vite 8 的实验性支持限制见 [依赖与工具链](DEPENDENCIES.md)。

运行依赖仅为 Zod。Svelte、二维码、图标和字体与构建 / 类型检查工具一起列为开发依赖，构建后通过 `dist` 提供给浏览器。Docker 运行阶段使用 `bun install --frozen-lockfile --production`，不安装前端或开发工具。

界面样式由 Svelte 模板中的 Tailwind 工具类组织；`src/app.css` 集中维护主题 token、`@layer base`、共享 `@utility` 和骰子动画配置。主题继续通过 CSS 媒体查询跟随系统，投票百分比保留运行时宽度绑定。断点、可访问状态与样式测试约定见 [样式指南](STYLING.md)。

一个服务实例对应一个 SQLite 数据库。在线连接表保存在进程内，不能将多个独立实例挂到同一个数据库后当作可水平扩展服务。扩容应先引入共享广播及房间所有权机制。

## 显式阶段

`lobby → briefing → investigation → negotiation → route_choice → execution → ending → debrief`

- 开始前检查 GM 席位和至少一名玩家；规则配置在开始后固定。
- 调查阶段自动公开三张证据。完整版完成三项准备；精简版不结算准备骰。
- 协商阶段自动发起预设安排投票；路线阶段自动发起路线投票。
- 路线确定后才进入执行。自创方案保存目标安排、代价与假设后自动重新开放投票，防止更改代价后沿用旧票。
- 执行按未结算目标开放检定，顺序可调整，同一目标只结算一次。
- 执行低骰且有物资时自动发起补救投票，处理后开放下一项行动。未决平票也属于阻塞操作，不能只看投票是否 closed。共用资格判断在 `shared/state.ts`。
- 三项执行结束进入交接；保存实际通报、负责人和更新时间后进入复盘。

GM 保留推进、断线处理、平票裁决、自创方案、叙事调整与人工报告核对。系统负责背景、消息、参与状态、计票、抽选、算式、后果、资源、进度与日志。

## 检定与投票

检定状态为 `recruiting → selected → resolved`。申请与协助均为明确回应；全员回应且有人申请时自动抽选，GM 可在离线成员尚未回应时从当前申请者抽选。服务端 `crypto.randomInt` 为每位申请者提供相等机会。主导记录提示轮换，不改变抽选概率。精简模式另记一名搭档，只有一人掷骰。重新招募保留目标占位、行动与 DC，但分配新检定 ID；旧轮次未送达的申请或实体骰不能进入新轮次。名单缩减使回应条件满足时也会抽选，投票仍只由 GM 手动结束。

虚拟骰由服务端生成，客户端传入骰点不参与生成。实体骰只接受 GM 的整数 1–20。行动、加成和 DC 在招募前确定；加成 / 创意依据说明为选填，留空或不传均可开始检定。准备与创意取最大降幅，原档与物资提升后的有效档分别保存。

投票名单固定为发起时的玩家，新加入者从下一轮参与。结束前仅发送已投票名单和自己的选择，GM 也看不到他人票。玩家可以反复改票，覆盖自己的原选项；全员投完或名单变化都不会自动结束。仅 GM 可以手动结束并公开计票，结束说明选填。唯一最高票选项当选，平票暂停推进，由 GM 记录理由选择平票项，或在路线阶段重新投票。GM 也可结束空投票，此时不产生决定或消耗物资；路线仍需重新投票确认后才能执行。结束后拒绝改票，双 GM 同时关票通过版本检查与事务保证只结算一次。

消费物资由服务器分档和投票结果共同验证。准备、成功、已补救检定不能消费。GM 可更正当前阶段最后一次已结算骰点：退回该次物资，按原 DC 重算并记录理由。更正后仍失败、有物资且有玩家时新开补救投票，不沿用旧票；历史空票或保留票不永久封锁当前补救。更早行动保留原记录；可以通过公开叙事和分项结果调整记录实际安排。

## HTTP

| 方法与地址 | 行为 |
| --- | --- |
| `GET /api/health` | 数据库可用性与协议版本 |
| `POST /api/rooms` | `{ name, settings: { mode, gmCount, dice } }` 创建场次 |
| `POST /api/rooms/:code/join` | `{ name }` 加入，默认玩家 |
| `POST /api/rooms/import` | `{ name, save }` 验证并创建新房间 |
| `GET /api/rooms/:code` | 当前成员最新完整投影 |
| `POST /api/rooms/:code/commands` | `{ id, revision, type, payload }` 写命令 |
| `GET /api/rooms/:code/export` | GM 完整存档，不含凭证 |

除创建和加入外，请求使用 `Authorization: Bearer <token>`。浏览器本地保存令牌，数据库只存 SHA-256 摘要。WebSocket 不把令牌放入 URL。房间码不授予 GM 权限，GM 席位只由房主分配。

命令和去重记录写入同一个 SQLite 事务。相同成员的相同命令 ID 重试只返回当前快照。GM 写操作校验 `revision`，冲突 `409` 包含最新投影。投票、申请、掷骰绑定具体 ID 和状态，接受同时提交；重复掷骰仍被状态机拒绝。交接报告由全部已加入成员（GM、玩家、观察者）共同编辑，所有人都可生成事实草稿、保存未完成内容。报告和私密笔记编辑保留起始版本，过期保存返回冲突，防止覆盖其他成员的更新。交接完整性仍由进入复盘时的检查保证。

Zod 验证输入。普通 POST 最大 1 MiB；存档文件最大 32 MiB，导入请求允许 32 MiB + 1 KiB 的 JSON 包裹余量。限制使用 UTF-8 实际字节，包括无 Content-Length 的流式请求。浏览器导入/导出使用 120 秒超时，普通 HTTP 请求仍为 12 秒。入站 WebSocket 消息最大 4 KiB，出站大快照背压预算为 64 MiB；创建、加入和命令分别限流。生产只读取 `dist`；开发 Vite 拒绝访问服务端私密模块、开发文档、数据库、剧情参考和环境文件。

开发 HTTP / WebSocket 代理显式保留 Host 和 Origin（`changeOrigin: false`），服务端比较实际来源和请求地址，不依赖局域网 HTTP 可能缺少的 `Sec-Fetch-Site`。不能把 `/api` 改成 Vite 字符串代理简写，该简写会重写 Host。反向代理若改写地址，需配置 `PUBLIC_ORIGIN`。

## WebSocket 与恢复

连接 `/ws` 后先发送 `{ type: 'auth', code, token }`；认证前不发送房间数据。成功后接收 `{ type: 'state', state: RoomView }`。客户端每 12 秒发送 `ping`，服务器回复 `pong`。无认证连接约 10–15 秒内关闭，已认证连接无心跳约 45–50 秒清除。在线名单按身份去重，多标签页关闭一个不会误报离线。

每次变化发送按权限裁剪的完整快照，客户端忽略旧版本。在线变化不增加 revision，因此实时连接中同版本 HTTP 不覆盖 socket 的在线名单，同版本 socket 快照仍可更新在线状态。重连采用退避与抖动，最高约十秒；重新联网、切回前台时恢复连接与补取快照。WebSocket 不可用时每七秒补取 HTTP 快照，操作等待实时连接恢复。断线不排队写命令；网络不确定的提交用相同命令 ID 重试。每次新 socket 有新代际；提交另有身份/操作生命周期，旧 HTTP、旧 socket 和已离开身份的回调不能改变当前状态或提交锁。401 进入 expired 并清理连接，联网/前台事件不自动重试无效凭证。

浏览器最后快照只用于阅读，不作为结算依据。局域网 HTTP 缺少 `crypto.randomUUID` 时用 `getRandomValues` 生成 UUID v4。本版没有 Service Worker，不承诺断网后首次加载；已经打开的页面可继续阅读。

## 本机草稿

`Room` 创建独立的 `room-drafts.ts` 仓库，并传给各页签/章节的编辑器。条件卸载或远端阶段切换不销毁草稿，原 revision 不自动更新。输入、取消重开和复核都有版本，异步保存不能关闭/清空新稿；检定结果和实体骰按 check ID 隔离。较早章节的草稿可从房间草稿面板查看/导出。

这些副本只在当前房间页面内存中，不发送给其他成员，也不等于共享保存。离开有丢弃确认，刷新/关闭有 beforeunload 提示；确认离开或刷新不承诺恢复。展示模式隐藏 GM 草稿并清理私密笔记，真正降权清除 GM 草稿。完整行为和无 DOM 测试边界见 [隐式状态机审查](STATE_MACHINE_AUDIT.md)。

## 存档与剧情

Room `schemaVersion=1`、应用剧本 `scenarioVersion=1.0.0` 保持不变；SQLite 升级为 `user_version=2`，当前导出 `green-light-save` v2，接受 v1/v2。旧数据库 v1 启动升级，旧 JSON 和 v1 缺少的 `archivedMembers` 在读取时补空数组，已有身份凭证不变；旧程序不能降级写入新库。导入仍校验目标唯一性、阶段前置条件、招募/主导、准备优势来源、算式与资源一致性。

恢复建立新房主和凭证，将实际历史成员放进无 role、无 active 席位的 `archivedMembers`，保留过去姓名/ID/记录，不继承令牌；40 人旧房间恢复后仍可邀请 39 人。`shared/members.ts` 仅供署名查询，认证、角色分配、招募/投票只用当前成员。补齐新 GM 后重新开放未完成申请或路线投票，不必手动把历史成员降为观察者。

投票保留最近 300 轮、日志最近 1500 条，更早明细不进入导出。`shared/archive.ts` 统一字节边界，`Store.save()` 提交前预算漂亮 JSON 以及最坏姓名/时间宽度的恢复版本；超额以 `archive_too_large` / 413 回滚，历史文本不被静默裁剪。`room.recovery` 是可替换的恢复上下文，不追加剧情日志；仅导入、未操作且没有历史引用的 `recoverySeat` 可在下次恢复时替换，实际执行命令后身份始终归档。这保证纯连续恢复不挤占字节预留。

中英内容在 `shared/content.ts` 成对定义，GM 私密提示在 `server/private-content.ts`。`docs/scenario/` 的剧本与 `content/scenario.zh-CN.json` 是开发参考，不被玩家端导入，也不进入运行镜像。内容边界见 [剧情与世界](SCENARIO.md) 和 [决定记录](DECISIONS.md)。中文字体由 Fontsource 自托管，图标使用 Font Awesome Free，许可证在 `public/licenses/`。
