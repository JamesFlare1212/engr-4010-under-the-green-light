# 网页版项目说明

## 当前实现范围（2026-10-21）

已按使用者要求实现多设备联网版本，采用 Bun、Svelte、Vite、TypeScript、SQLite、Tailwind CSS，提供 Docker Compose。包括房间码 / 链接 / 二维码、GM 数量、实体与虚拟骰、自动内容展示、投票、随机主导抽选、流程分叉、中英文、刷新和断线恢复。下文“同屏首版”为准备阶段历史建议，已由此次范围扩展；运行说明见 [README](../README.md)，协议见 [实现说明](ARCHITECTURE.md)。

## 要提供的体验

让两名 Co-GM 能用一个网页主持《绿灯之下》，按情节发放证据、记录玩家的路线与行动、结算 D20 和补救资源，最后形成可复盘的事故交接记录。

首版建议采用**同屏、GM 操作、本地保存**的课堂模式：六名玩家讨论和掷实体骰，网页帮助主持和记录；也可以提供屏幕掷骰选项。技术栈仍待开发时决定。

## 用户与信息边界

- **GM**：看见剧情真相、NPC 说明、后果分档、下一步提示和状态编辑。
- **玩家**：看见公共危机、证据、路线代价、行动目标、已公开结果和复盘。
- **交接者**：能恢复一场游戏，理解已做决定、剩余物资、待援人员和下次行动。

即使采用同一个页面，也应有清楚的“主持视图 / 展示视图”切换。GM 私密说明应在展示视图中隐藏。若以后加入联网同步，信息权限需要在服务端重新设计。

## 首版功能建议

1. 新建场次：选择完整或简版，登记临时玩家名，确认采用的规则。
2. 故事推进：开场 → 调查 → NPC 协商 → 路线 → 三次执行 → 结局 → 复盘。
3. 证据卡和 NPC：按需展示；公开证据始终可回看。
4. 路线选择：A/B/C 或自创；记录接受的代价和假设。
5. 行动结算：输入骰点、相关加成、准备/创意优势；显示 DC、差额、结果和可用补救。
6. 全员参与：提示尚未主导行动的人；GM 可调整顺序与角色。
7. 场次保存和恢复：本地保存，导入/导出 JSON；保存游戏版本和完整决策记录。
8. 收尾：分别总结人员、设施、信任，生成简短事故报告和复盘提示。

## 界面组织建议

同屏主持可分为剧情主区、当前目标与参与者、常驻状态栏。状态栏显示已完成目标、剩余物资、准备优势和待办交接。把算式及后果放在行动结算处，路线选择处先展示代价。

现场以鼠标、触屏或键盘均可操作；长文和卡片适合投影阅读。对色彩状态同时提供文字，切换展示视图时保留当前位置。倒计时如加入，应明确区分真实课堂时间与故事时间，并允许 GM 暂停。

## 开发边界与后续扩展

本仓库先提供一份故事和可改规则。账户、多人联网、远程评价提交、排行榜、其他 campaign、复杂战斗系统和部署平台均为后续范围，未作产品承诺。Co-GM 正式评价由课程现有流程完成。

## 完成标准

同一网页能从开场走到复盘；刷新后恢复当前场次；同一目标无法意外重复扣物资；失败仍能推进；所有事实和公开代价能在玩家视图中查阅；游戏结果不会被显示成伦理评分或课程成绩。
