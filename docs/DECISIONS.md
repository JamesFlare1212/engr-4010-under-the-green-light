# 当前决定与待定事项

## 已确定的交接内容

- 项目名为 `engr-4010-under-the-green-light`，围绕《绿灯之下》准备网页版。
- 既有原件、原创草案和提取文本分开保存；反馈评语、报名照片、Office锁文件、登录资料不属于这个开发材料包。
- 玩法以本次 GM 剧本为准；JSON 是便于开发的结构化摘录。课程原规则优先于草案约定。
- 后果分别记录人员、设施、信任和路线代价；不形成“道德总分”。
- 关键证据直接可得；掷骰结算准备和执行质量。

## 草案新增机制，需在采用时明确

- 每骰只选一种最相关加成，未默认叠加到+6。
- 差额0、+1、+2均算成功，补齐正式表未明确列出的+1/+2。
- 自然1按普通算式结算，不额外引入灾难规则。
- 准备或具体创意最多降低一个对应目标的DC 2，二者取较高者。
- 两份全组应急物资，执行掷骰后可提升一档；每骰最多一份，最高普通成功。
- 三条路线都做三个执行检定，基础DC 12 / 12 / 13。

## 首版建议，尚非实现决定

- 同屏、GM主导、本地存档；中文主持说明与英文台词兼容。
- 实体骰输入为可用方式，屏幕掷骰可作为选项。
- 应用内用数据模型组织内容，独立实现规则与视图。

## 2026-10-21 实施决定

- 使用者明确扩展为多设备联机，选择 Bun、Svelte、Vite、TypeScript、SQLite、Tailwind CSS 和 Docker Compose；此前同屏、本地存档建议不再作为产品边界。
- 服务端显式状态机决定推进条件。HTTP 命令有幂等 ID，SQLite 事务保存状态与去重记录；双 GM 使用版本冲突处理并发。WebSocket 发送按权限裁剪的投影。
- 房主分配 1–4 个 GM 席位（两个为 Co-GM），成员自行选择角色分工。称号不限制技能，不引入课程成绩或伦理总分。
- 协商、路线和补救采用预设投票，由 GM 手动结束并计票；结束前玩家可随时改票，全员投完或成员身份变化不自动关票。唯一最高票选项当选，平票由 GM 公开理由裁决。结束说明选填；空投票不产生决定或物资消耗。
- 多人申请时等概率随机选一位；主导次数提示轮换，不改变抽选概率。精简版记录搭档，仍只有一个掷骰人。
- 实体骰由 GM 每次录入；虚拟骰由服务器产生，客户端显示动画。准备成功降 DC 2，准备 / 创意取较高者，既定分档与补救规则保持不变。
- 按使用者要求，加成 / 创意依据说明改为选填；前端允许留空，服务端也接受省略，存档统一保存为空字符串。
- 系统展示背景、证据、NPC 消息、结果和后果；GM 保留自创路线、实际叙述和分项结果调整。通报真实性独立于骰点。
- 按使用者要求，handover 交接报告由所有成员共同填写（包括玩家与观察者），均可保存、生成草稿和人工核对；未完成内容可先保存，报告完整后由 GM 推进复盘。保留版本检查和公开保存者记录。
- 应用改编版本 1.0.0，存档 `green-light-save` v1。原种子、GM / 玩家 Word、文本与独立流程图仍是 0.1.0-draft 来源。网页内容单独存放，不宣称与 Word 自动互转。
- 保留 evidence / NPC / route / objective ID、12 / 12 / 13 基础 DC、保障事实、既定结果与原英文开场。新增双语摘要、预设协商、行动与投票属于应用适配，不改写课程规则或世界既有设定。测试核对关键 ID、DC 与英文开场。
- 不公开 `materials`、原始种子或私密模块。中文字体通过 Fontsource Noto Sans SC 自托管，不依赖运行时 Google Fonts 网络。
- 导入创建新房间，保留历史行动与报告，不继承旧令牌。未完成申请需重新开放；房主将不再参与的历史身份设为观察者。无跨设备账号找回。
- 单服务实例，进程内广播；课堂计时独立于故事时间。断线只读，恢复后使用服务端快照。
