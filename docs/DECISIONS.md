# 应用与剧情决定

## 内容边界

- 课程机制提供 D20、GM 设置 DC、相关加成与五档叙事结果的基础。具体阈值补齐、单一加成、准备 / 创意降难度及应急物资是本剧本的场次约定，不作为通用课程规定。
- Guardians 世界已有 Nemorath、Heliora Prime、The Shell、Luminis Sea、公会协作使命、恶海鸥和 Maid-Mer；本事件不改写既有运输船和其他公会的剧情。
- 泵站、十二名维修人员、三名 NPC、冻结绿灯、避难室、医疗备用、路线代价及其数值属于《绿灯之下》的虚构设计。
- 人员、设施、通报真实性和路线代价分别记录。游戏不产生伦理总分或课程成绩。

## 当前实现

- 多设备联机，Bun / Svelte / Vite / TypeScript / SQLite / Tailwind CSS，使用 Docker Compose 部署。单个服务实例负责数据库和房间广播。
- 服务端显式状态机、SQLite 事务和命令去重决定规则结果；WebSocket 只发送按权限裁剪的完整快照。GM 操作检查版本，断线时只读。
- 房主分配 1–4 个 GM 席位，成员自选角色分工。称号不限制技能，不额外加点。
- 协商、路线和补救通过投票，由 GM 手动结束。结束前可改票且隐藏选择，全员投完也不自动关票；平票由 GM 说明理由裁决，空投票不产生决定。
- 多人申请时等概率随机选择一名主导，主导记录用于提醒轮换。精简版记录搭档，仍只有一个掷骰人。
- 实体骰由 GM 录入；虚拟骰由服务器生成。每次选一个加成，准备与创意取较高降幅；自然 1 不增加额外处罚。加成 / 创意依据说明为选填。
- GM 可使用自创路线、重排执行目标、记录实际叙述及调整分项结果。更改自创方案后重新投票，不沿用对旧方案的选择。
- 所有成员包括观察者都可编辑交接、生成事实草稿和保存未完成内容；进入复盘仍由 GM 操作，并检查实际通报、负责人和更新时间。
- 中英内容使用相同 ID，非预设的输入保留原语言。语言和明暗主题跟随浏览器偏好；语言按钮提供临时切换。
- 存档版本为 `green-light-save` v1，剧情版本为 1.0.0；导入创建新房间，不继承旧登录权限。
- 图标和字体本地打包，许可证留在 `public/licenses/`；运行时不依赖外部字体服务。

## 剧本参考与线上适配

`docs/scenario/` 保留原场次的 GM 叙述和英文玩家资料，`content/scenario.zh-CN.json` 保留 `0.1.0-draft` 结构化参考。线上内容在 `shared/content.ts` 和 `server/private-content.ts` 独立维护；这些文件之间没有自动导入或文档生成流程。

保留稳定的 evidence / NPC / route / objective ID、12 / 12 / 13 基础 DC、保障事实、既定后果与原英文开场。双语摘要、预设协商、行动和投票属于线上适配。

原稿建议两位 Co-GM、固定时长与轮流主导。线上游戏允许 1–4 个 GM 席位，系统随机选主导；课堂计时和故事十二分钟独立。具体推进与规则行为以 [开发交接](DEVELOPMENT_HANDOFF.md) 和状态机为准。

仓库范围为线上游戏及必要的开发资料。课程附件、公会作业、Office 文档、旧独立流程图与 PDF 提取 / Word 生成工具已移除；历史版本可从 Git 历史查阅。保留剧本不代表对课程材料或同学作品授予再分发许可，来源说明见 [SOURCES](SOURCES.md)。
