# 开发交接：规则、状态与验收

线上游戏使用 Bun、Svelte 5、Vite 8、TypeScript、SQLite 和 Tailwind CSS 4。运行与检查从 [README](../README.zh-CN.md) 开始；依赖版本与升级检查见 [依赖与工具链](DEPENDENCIES.md)，网络协议见 [实现与协议](ARCHITECTURE.md)，剧情资料入口见 [剧情与世界](SCENARIO.md)。

## 修改入口

| 内容 | 文件 |
| --- | --- |
| 公共双语剧情、行动、投票、后果 | `shared/content.ts` |
| GM 私密真相与提示 | `server/private-content.ts` |
| 状态、协议、存档类型 | `shared/types.ts` |

| SQLite、幂等命令、权限投影 | `server/store.ts` |

## 状态转换与推进条件

`lobby → briefing → investigation → negotiation → route_choice → execution → ending → debrief`

1. 房主分配 1–4 个 GM 席位；至少一名玩家参与才能开始。模式和骰子设置在开始后固定。
2. 调查公开全部关键证据。完整版完成三项准备检定；精简版跳过准备，保留执行基础 DC 与两份物资。
3. 协商、路线和补救均由 GM 手动结束投票；结束前可改票，任何人都看不到他人选择。平票由 GM 记录理由裁决；空投票不产生决定。
4. 路线确定后进入执行。GM 公布行动、备用方案和 DC；玩家申请主导或协助，系统从申请者中等概率抽选一位。主导记录只提示轮换，不改变概率。
5. 检定为 `recruiting → selected → resolved`。虚拟骰仅由抽中的玩家触发，服务端生成点数；实体骰由 GM 录入 1–20 的整数。
6. 同一执行目标只结算一次，三个目标可以重排。低骰且尚有物资时自动发起补救投票，处理完后继续下一目标。
7. 三项目标完成后共同编辑交接。所有成员可生成草稿、保存未完成内容；实际通报、具名负责人和更新时间齐全后，GM 才能进入复盘。

GM 可以自创路线、调整叙事和人员 / 设施实际结果。自创路线更改后重新投票；玩家应在接受路线前看见代价与假设。

## 检定算式

```text
selectedBonus = 0、+1 工具、+2 工程或 +3 领导力，选一个
reduction = max(preparationReduction, creativeReduction)，范围 0..2
effectiveDC = baseDC - reduction
total = d20 + selectedBonus
delta = total - effectiveDC
```

加成与创意依据说明为选填。准备 DC 为 11，成功或获益提供对应执行 DC 降 2。执行基础 DC：通路 12、转移 12、隔离 13。自然 1 按普通差额结算。

| 差额 | 档位 |
| --- | --- |
| `delta <= -5` | `consequences`：失败并有后果 |
| `-4..-3` | `twist`：失败但有转机 |
| `-2..-1` | `near_miss`：部分成功 |
| `0..2` | `success`：成功 |
| `>= 3` | `boon`：成功并获益 |

准备失败仍给出全部关键证据，不追加执行罚点。每次失败执行最多用一份应急物资提升一档，最高普通成功；成功、获益和准备检定不能消耗物资。提升采用新档完整后果，路线已接受的代价仍保留。

## 状态与持久化约束

- 原始骰点、基础档与补救后的有效档分开记录。幂等命令 ID 与状态在同一 SQLite 事务保存，重试不能重复扣物资。
- GM 更正当前阶段最后一次已结算骰点时，先退回该次物资，再按原 DC 重算并记录理由。更早的行动保持历史，通过公开叙事记录后续调整。
- GM 写操作检查版本；并发冲突返回最新投影。玩家申请与投票绑定对应 ID，可以并发提交。
- 人员、隔离、医疗交接和实际通报分别记录。低骰不删除证据或阻断后续目标；隔离失败不撤销已完成的人员转移，也不取消避难室保障。
- 事实与未知由成员实际表达决定。高骰不把虚假通报改成真实，低骰不把诚实表达改成欺骗；不生成伦理总分或课程成绩。
- 客户端只接收权限投影。GM 私密上下文和笔记留在服务端；断线时只读，恢复后采用服务端快照。
- 导出 `green-light-save` v1；导入校验版本、算式、资源及目标唯一性，创建新房间并重新建立身份，不继承旧令牌。

## 关键验收

1. 完整与精简模式可从开场走到复盘，全部低骰仍有可继续的救援、封锁和后续安排。
2. 差额 `+2/+3/-2/-3/-5` 正确落档，准备与创意都为 2 时仍只降 2。
3. 差额 −3 花一份物资只从转机升到部分成功；重复请求不能再扣物资。
4. 人员已撤离而隔离失败时，保留人数并追加设施和供电待办。
5. 全员投票后仍可改票，只有 GM 关票后公开计票；平票、空票和双 GM 竞争正确处理。
6. 玩家不能执行 GM 操作或获取私密内容；只有选中的玩家能触发虚拟骰。
7. 未完成交接可保存；过期编辑不能覆盖新版本；报告完整后才能进入复盘。
8. 刷新、重连、SQLite 重启与存档导入保留进度，权限、资源和状态保持一致。

执行 `bun run check`、`bun test tests`、`bun run build`。验证范围及平台限制记录在 [QA](QA.md)。修改剧情时同时核对双语文本、私密真相、剧本参考和内容回归测试；修改存档结构时显式处理版本兼容。
